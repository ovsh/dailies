# Phase 5: Build the local diagnostics foundation

[Back to the plan](README.md)

## Goal

Record a bounded, structured timeline for every important operation without recording user content. Local diagnostics must work offline and must not depend on Sentry.

## Core contract

Use a small port with immutable child scopes:

```ts
interface DiagnosticScope {
  child(context: Partial<CorrelationContext>): DiagnosticScope;
  record(event: DiagnosticEvent): void;
  capture(error: unknown, spec: IncidentSpec): IncidentId;
  flush(deadlineMs: number): Promise<void>;
}
```

- `DiagnosticEvent` is a discriminated union with a fixed payload for each event name.
- Do not permit `Record<string, unknown>`, printf-style messages, or raw object serialization.
- Do not introduce a general event bus, telemetry database, or `AsyncLocalStorage`.
- A semantic owner emits the event once. Retries are transitions. The final owner captures one terminal incident.

## Correlation ownership

| Identifier | Owner and lifetime |
| --- | --- |
| `sessionId` | Random UUID created during main bootstrap for each launch |
| `projectRef` | HMAC of the existing project UUID with a local random salt |
| `runId` | New UUID each time a project is activated |
| `jobId` | Existing database job ID, always paired with project key and run ID |
| `turnId` | Existing chat correlation changed to a UUID |
| `incidentId` | Generated by the diagnostics facade for one terminal problem |

Do not create a stable user, hardware, device, or installation ID. Do not use a project name or raw project ID remotely. Rotate the HMAC salt when local diagnostics are cleared. `projectRef` may be included as remote structured context after consent, but never as an indexed tag.

Main creates `sessionId` and exposes it read-only during preload and renderer bootstrap. Renderer input can never replace it. Project, run, job, and turn correlation stays in the main process in version 1. Do not add general trace-header propagation across every IPC call.

## Allowed events

Start with this bounded catalog:

| Event | Allowed fields |
| --- | --- |
| `app.session` | transition, previous exit classification, duration |
| `process.failure` | process kind, Electron exit reason and code, safe error code, incident ID |
| `ipc.call` | constant channel, duration, outcome, safe error code |
| `project.run` | transition, aggregate job counts, duration |
| `pipeline.job` | stage, transition, job ID, attempt, duration, safe error code |
| `pipeline.health` | timed out or recovered, stage, age, deadline, active and queued counts |
| `model.call` | operation, configured model ID, HTTP status, duration, retry or fallback, provider request ID |
| `agent.turn` | transition, iteration count, constant tool name, duration, safe error code |
| `update.operation` | check trigger, state transition, version, duration, safe error code |
| `ui.failure` | screen constant, action constant, safe error code, incident ID |
| `diagnostics.dropped` | event count and level bucket |

Do not log refresh polls, frame updates, media range requests, progress pulses, successful read-only getters, or every model token.

## Error handling

Create a `classifyIncident` function that returns only:

```ts
type SafeFrame = {
  bundle: "main" | "preload" | "renderer";
  asset: BuildAssetId;
  line: number;
  column: number;
};

type SafeIncident = {
  code: SafeErrorCode;
  retryable: boolean;
  frames: SafeFrame[];
};
```

- Known failure branches map to stable codes at their owner. UI copy comes from a closed code-to-copy map and is not stored in events.
- Parse a raw stack only in memory. Keep frames whose normalized file matches an asset in generated `build-info.json`, convert that file to its closed `BuildAssetId`, and retain only line and column. Drop frame text and every external frame.
- Unknown names, messages, stacks, and causes are discarded after classification. Use `UNCLASSIFIED_FAILURE` when no known code applies.
- Never persist a raw `Error`, never serialize `cause`, and never pass either to a remote adapter.

## Local file policy

Use the main process as the only file writer. Renderer and preload emit already typed events through a private diagnostics IPC channel. The main process validates again.

- JSON Lines format, one envelope per line
- asynchronous file writes with explicit owner-only `0600` mode
- 5 MiB per file
- current file plus two archives
- delete archives older than seven days at startup
- no compression, encryption scheme, or separate retry queue in version 1
- best-effort flush with a 1.5 second deadline during shutdown

Configure `electron-log` with asynchronous file transport, explicit `0600` write mode, JSONL-only formatting, and size-based rotation. Assert those settings against the pinned package version because its defaults are synchronous and broader. No console monkeypatching is allowed.

## Process coverage

Initialize diagnostics immediately after the optional `DAILIES_USER_DATA` override and before `app.whenReady()` work.

- Replace the current synchronous `appendFileSync` and console overrides.
- Install one fatal `uncaughtException` handler. It classifies a closed incident, stops application work, starts a hard 750 ms timer, asks local and consented remote sinks to flush within that bound, then calls `process.exit(1)` in every branch. It never resumes normal work. Delivery is best effort when the network or runtime is already broken.
- Record `unhandledRejection`, then follow an explicit fatal or recoverable policy at the owning boundary.
- Record safe metadata from `render-process-gone`, `child-process-gone`, `unresponsive`, and `responsive`.
- Add a React Error Boundary at renderer bootstrap.
- Route renderer `error` and `unhandledrejection` events through `classifyIncident`, then discard the raw event values.
- Wrap preload API entry points so a preload failure produces a closed incident before its raw value crosses a boundary.
- Make `runIpc` report one sanitized UI incident instead of discarding the original error.

## Privacy harness

Create fixtures containing:

- a fake API key and authorization header
- a home-directory path and media filename
- a project and episode name
- prompt, transcript, note, and model-response fragments
- URL-encoded and JSON-escaped forms of each value
- a provider error body and query string

Run every fixture through known errors, unknown errors, event serialization, rotation, and diagnostic IPC. The test fails if any forbidden value reaches a sink.

## Tests

### Static

- Exhaustive event union tests and compile-time payload rejection.
- Sanitizer mutation tests for escaped and encoded forbidden values.
- File rotation, age pruning, permissions, and repeated initialization.
- One terminal incident for a retry sequence.
- No raw IPC arguments or results in diagnostic events.

### Runtime

- Use a fresh isolated profile and trigger controlled main, renderer, preload, pipeline, and model failures.
- Search local JSONL by session, job, turn, and incident IDs.
- Emit enough events to rotate files and prove disk use remains bounded.
- Crash the test process and confirm the observer does not keep it running.

## Gate

Phase 5 is complete when all controlled scenarios are reconstructable from bounded JSONL, every forbidden fixture is absent, early failures are visible, and logging cannot keep a fatally broken process alive.

## Principles

Model the Domain and Type System Discipline replace loose log objects with a closed event catalog. Boundary Discipline sanitizes before persistence and validates diagnostics IPC. Minimize Reader Load keeps one facade and semantic ownership. Laziness Protocol rejects a telemetry database, event bus, and custom backend.
